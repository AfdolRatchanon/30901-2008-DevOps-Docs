1.  สาระสำคัญ (Concept) 
	หัวใจสำคัญของกระบวนการ DevOps คือการสร้างซอฟต์แวร์ที่มีความน่าเชื่อถือสูงและพร้อมใช้งาน การทดสอบซอฟต์แวร์อัตโนมัติ (Automated Testing) จึงเป็นเครื่องมือที่ช่วยยืนยันว่าโค้ดที่เขียนหรือแก้ไขใหม่ทำงานได้ตามความต้องการและไม่กระทบส่วนอื่น สัปดาห์นี้จะมุ่งเน้นการทำความเข้าใจกลยุทธ์การทดสอบ (Testing Strategy) ตั้งแต่ระดับ Unit, SIT ไปจนถึง UAT และเรียนรู้การเขียน Unit Test ซึ่งเป็นการทดสอบในหน่วยที่เล็กที่สุดของโปรแกรม โดยใช้เฟรมเวิร์กอย่าง Jest รวมถึงแนวคิดการพัฒนาที่ขับเคลื่อนด้วยการทดสอบ (Test-Driven Development: TDD)

2.  สมรรถนะหลัก/ย่อย (Unit of Competence / Element of Competence)
1. มีความเข้าใจกลยุทธ์การทดสอบซอฟต์แวร์ในระดับต่างๆ
2. สามารถเขียนและตั้งค่าเครื่องมือสำหรับ Unit Testing ได้
3. มีทักษะในการวิเคราะห์ความครอบคลุมของการทดสอบ (Test Coverage)
4. ปฏิบัติงานด้วยความละเอียดรอบคอบเพื่อป้องกันข้อบกพร่อง (Bug)

3.  จุดประสงค์เชิงพฤติกรรม (Behavioral Objective)
1. อธิบายระดับของการทดสอบ (Unit, SIT, UAT) และกลยุทธ์การทดสอบในระบบ DevOps ได้
2. ติดตั้งและใช้งานเฟรมเวิร์ก Jest สำหรับทดสอบโค้ดภาษา JavaScript/TypeScript ได้
3. เขียนโค้ด Unit Test สำหรับทดสอบฟังก์ชันพื้นฐานได้อย่างถูกต้อง
4. อธิบายแนวคิดของการพัฒนาโปรแกรมแบบ Test-Driven Development (TDD) ได้
5. สรุปความสำคัญและประโยชน์ของการทำ Unit Testing ลงในสมุดจด
6. แสดงความสนใจต่องานที่ได้รับมอบหมายได้เป็นอย่างดี
7. ประยุกต์ใช้ Unit Testing ในการสร้างความมั่นใจก่อนส่งมอบซอร์สโค้ด
8. ปฏิบัติงานด้วยความรอบคอบและหมั่นตรวจสอบความถูกต้องของ Logic อย่างสม่ำเสมอ

Testing Strategy
ใน DevOps เราแบ่งการทดสอบออกเป็นหลายระดับเพื่อให้ครอบคลุมความเสี่ยงทั้งหมด
1. Unit Testing: ตรวจสอบระดับ "ฟังก์ชัน" เล็กที่สุด ว่าทำงานตามลอจิกได้ถูกต้องหรือไม่ มักจะเขียนและรันโดยโปรแกรมเมอร์ (ความเร็วสูงที่สุด)
2. Integration Testing (SIT): ตรวจสอบการเชื่อมต่อระหว่างฟังก์ชันหรือระบบย่อย (เช่น API คุยกับ Database)
3. User Acceptance Testing (UAT): ตรวจสอบจากมุมมองของผู้ใช้งานจริง (ส่วนมากคลิกผ่านหน้าจอ UI)

Jest (JavaScript/TypeScript Testing Framework)
เป็นเครื่องมือที่ใช้รันการทดสอบโดยจะทำหน้าที่ค้นหาไฟล์ชื่อ `*.test.js` หรือ `*.test.ts`
โครงสร้างพื้นฐานของชุดทดสอบ (Test Case):
- `describe()`: ใช้เพื่อจัดกลุ่มการทดสอบที่เกี่ยวข้องเข้าด้วยกัน
- `it()` หรือ `test()`: ใช้เพื่ออธิบายสิ่งที่ต้องการทดสอบใน 1 กรณีย่อย
- `expect().toBe()`: เป็นคำสั่งเพื่อยืนยัน (Assert) ว่าผลลัพธ์ที่ได้ตรงกับที่คาดเดาไว้หรือไม่
ตัวอย่าง:
```javascript
test('brings 1 + 2 to equal 3', () => {
  expect(sum(1, 2)).toBe(3);
});
```

Test-Driven Development (TDD)
แนวคิดการพัฒนาที่ "เขียนตัวทดสอบ (Test)" ก่อนที่จะเขียน "โค้ดจริง" เริ่มจากสร้าง Test ที่ล้มเหลว (Red) จากนั้นเขียนโค้ดเพื่อให้ Test ผ่าน (Green) และปรับปรุงโค้ดให้สะอาดขึ้น (Refactor)
