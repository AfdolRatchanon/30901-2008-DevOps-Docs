1.  สาระสำคัญ (Concept) 
	การประเมินผลงานแบบโปรเจกต์ (Project-based Assessment) เป็นการเปิดโอกาสให้ผู้เรียนนำความรู้ด้าน DevOps (Linux, Shell Script, Git, Docker) ที่ได้เรียนรู้มาตั้งแต่ต้นภาคเรียน มาประยุกต์ใช้ร่วมกันผ่านโปรเจกต์ Task Tracker ผู้เรียนจะต้องส่งมอบโปรเจกต์ที่สามารถทำงานได้จริงบนสภาพแวดล้อม Container พร้อมกับมีประวัติการจัดการโค้ด (Git History) ที่เป็นระบบตามมาตรฐาน Conventional Commits การนำเสนอผลงานยังเป็นการฝึกทักษะการสื่อสารเชิงเทคนิค และการรับข้อเสนอแนะผ่านกระบวนการ Code Review ร่วมกัน

2.  สมรรถนะหลัก/ย่อย (Unit of Competence / Element of Competence)
1. สามารถบูรณาการความรู้ด้าน DevOps เพื่อพัฒนาและจัดการสภาพแวดล้อมโปรเจกต์
2. มีทักษะในการนำเสนอโครงสร้างโปรเจกต์และอธิบายวิธีการนำไปใช้งาน
3. สามารถจัดทำคู่มือ (README) ที่ครอบคลุมและเข้าใจง่าย
4. มีความกล้าแสดงออก รับฟังความคิดเห็น และนำเสนอผลงานทางเทคนิคได้อย่างมีประสิทธิภาพ

3.  จุดประสงค์เชิงพฤติกรรม (Behavioral Objective)
1. นำเสนอและสาธิตการรันโปรเจกต์ Task Tracker ให้สามารถทำงานได้จริงตามโจทย์ที่กำหนด
2. อธิบายโครงสร้างของไฟล์ Dockerfile และ docker-compose.yml ของระบบตนเองได้
3. แสดงการควบคุมเวอร์ชันโค้ด (Git History) ได้อย่างเป็นระบบตามมาตรฐาน
4. จัดทำและอธิบายข้อมูลในไฟล์คู่มือ README.md ได้อย่างชัดเจน
5. นำเสนอผลงานของกลุ่มตนเองหน้าชั้นเรียนได้อย่างฉะฉาน
6. แสดงความสนใจต่อผลงานเพื่อน และแลกเปลี่ยนข้อคิดเห็น (Code Review) ได้เป็นอย่างดี
7. ประยุกต์ความเห็นจากผู้สอนไปปรับปรุงแก้ไขโปรเจกต์ให้สมบูรณ์ขึ้น
8. ปฏิบัติงานด้วยความรอบคอบ ไม่มีการเผลอนำข้อมูลที่เป็นความลับ (Secret / .env) ขึ้นใน Repository

5.  กิจกรรมการเรียนรู้ (Teaching / Learning Activities)
	-  การเรียนรู้แบบโครงงานเป็นฐาน (Project-based Learning) ให้ผู้เรียนนำเสนอโปรเจกต์ที่สะสมผลงานมาตั้งแต่ต้น และรับการตรวจประเมินตามเกณฑ์ Checklist ของ Midterm

โครงสร้างและองค์ประกอบของโปรเจกต์ (Milestone M1-M4)
- M1: โครงสร้างโฟลเดอร์มีระเบียบ, จัดเตรียมไฟล์ README.md สำหรับอธิบาย และตั้งค่า .gitignore
- M2: จัดทำสคริปต์อัตโนมัติ `setup.sh` 
- M3: การทำ Version Control อย่างเป็นระบบ มีการตั้งค่าการเขียน Commit message มาตรฐาน (Conventional Commits เช่น feat: , fix: ) การจำกัดสิทธิ์บน GitHub และ Branch Protection 
- M4: ระบบคอนเทนเนอร์ มีไฟล์ Dockerfile แบบ Multi-stage รันได้ไว และ docker-compose.yml 

เกณฑ์การประเมินคุณภาพ
- App Execution: โปรเจกต์สามารถเปิดขึ้นมารันได้โดยไม่เกิด Error ตั้งแต่เริ่มต้น และสามารถเรียกใช้ API (GET, POST, PUT, DELETE) ได้ตามที่โจทย์ระบุ
- Docker: ใช้งานคำสั่ง docker compose up แล้วได้ผลเป็น (healthy) สำหรับ Service ทั้งหมด โดยไฟล์ขยะ (node_modules) ไม่ถูกก๊อปปี้เข้าไปด้วย
- GitHub Repo: สะอาด ไม่มีการ Commit ไฟล์ `.env` เข้ามาในระบบเด็ดขาด
