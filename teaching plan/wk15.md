1.  สาระสำคัญ (Concept) 
	การนำซอร์สโค้ดที่ผ่านการทดสอบคุณภาพไปติดตั้งลงบนสภาพแวดล้อมที่ใช้งานจริง (Production Deployment) ถือเป็นขั้นตอนสำคัญที่จะเชื่อมโยงงานของนักพัฒนาเข้ากับผู้ใช้งาน หลักการ The Twelve-Factor App เป็นแนวทางปฏิบัติที่ดีที่สุด (Best Practices) สำหรับการสร้างและนำแอปพลิเคชันขึ้นสู่คลาวด์ ซึ่งรวมถึงการจัดเก็บโครงสร้างพื้นฐานต่างๆ ให้อยู่ในรูปแบบของโค้ด (Infrastructure as Code - IaC) ทำให้กระบวนการติดตั้งสามารถทำซ้ำได้และลดข้อผิดพลาด สัปดาห์นี้จะมุ่งเน้นการนำแอปพลิเคชันขึ้นบนระบบ Cloud (เช่น Render หรือ Railway) และการตั้งค่า Environment Variables อย่างปลอดภัย

2.  สมรรถนะหลัก/ย่อย (Unit of Competence / Element of Competence)
1. เข้าใจหลักการและกระบวนการนำแอปพลิเคชันไปติดตั้งบนคลาวด์
2. สามารถใช้แนวคิด The Twelve-Factor App เพื่อออกแบบระบบที่ยืดหยุ่นได้
3. มีทักษะในการตั้งค่า Environment Variables แยกจากซอร์สโค้ดเพื่อความปลอดภัย
4. ปฏิบัติงานด้วยความรอบคอบและให้ความสำคัญกับความปลอดภัยของระบบจริง

3.  จุดประสงค์เชิงพฤติกรรม (Behavioral Objective)
1. อธิบายกฎและข้อควรปฏิบัติที่สำคัญตามหลัก The Twelve-Factor App ได้
2. อธิบายแนวคิดเบื้องต้นของการจัดการ Infrastructure as Code (IaC) ได้
3. ตั้งค่าการเชื่อมต่อระหว่าง Repository และผู้ให้บริการ Cloud ได้สำเร็จ
4. ติดตั้ง (Deploy) แอปพลิเคชัน Task Tracker ขึ้นสู่ระบบคลาวด์สาธารณะได้
5. สรุปความสำคัญของการแยก Environment Variables ลงในสมุดจด
6. แสดงความสนใจต่องานที่ได้รับมอบหมายได้เป็นอย่างดี
7. ประยุกต์ใช้ความรู้เพื่อทำให้ระบบสามารถสเกล (Scale) และนำไปใช้ที่ใดก็ได้
8. ปฏิบัติงานด้วยความรอบคอบในการจัดการคีย์และตัวแปรในระบบ Production

The Twelve-Factor App
เป็นแนวปฏิบัติสำหรับการออกแบบแอปพลิเคชันให้พร้อมสำหรับคลาวด์ (Cloud-Native) ข้อสำคัญที่ควรรู้ได้แก่:
1. Codebase: แอปหนึ่งตัว มี Codebase เดียวแต่สามารถนำไป Deploy ได้หลาย Environments (Dev, Staging, Prod)
3. Config: เก็บค่าการตั้งค่า (เช่น URL ของ Database, Password) ไว้ใน Environment Variables เสมอ ห้ามเก็บในซอร์สโค้ด
6. Processes: แอปต้องไม่บันทึกหรือเก็บสถานะไว้ในตัวเอง (Stateless) ข้อมูลที่ต้องเก็บถาวรให้ส่งไปที่ Database

Cloud Deployment (PaaS)
PaaS (Platform as a Service) เป็นผู้ให้บริการคลาวด์ที่จัดการระบบปฏิบัติการ (OS) เครือข่าย และเซิร์ฟเวอร์ให้แล้ว (เช่น Render, Railway, Heroku) นักพัฒนาเพียงแค่เตรียมซอร์สโค้ด หรือ Docker Image ระบบจะทำการ Build และนำขึ้นให้บริการเป็นเว็บไซต์ (Public URL) ให้โดยอัตโนมัติ 

Infrastructure as Code (IaC)
แนวคิดในการจัดการเซิร์ฟเวอร์ โดยเปลี่ยนจากการใช้คนเข้าไปกดตั้งค่าที่ละเซิร์ฟเวอร์ มาเป็นการ "เขียนโค้ด" เพื่อสร้างและตั้งค่าโครงสร้างพื้นฐานแทน ทำให้ลดข้อผิดพลาด จัดเก็บเป็นเวอร์ชัน (Version Control) และสามารถสั่งสร้างใหม่กี่ครั้งก็ได้ผลเหมือนเดิม (Reproducible)
