1.  สาระสำคัญ (Concept) 
	การพัฒนาโปรแกรมยุคใหม่ต้องการความรวดเร็วและความถูกต้อง การนำซอร์สโค้ดไปติดตั้งสู่ผู้ใช้งาน (Deployment) ด้วยมือแบบเดิม (Manual) มักก่อให้เกิดข้อผิดพลาดและใช้เวลานาน กระบวนการ Continuous Integration (CI) และ Continuous Deployment (CD) จึงถูกนำมาใช้เพื่อให้การทดสอบ การสร้าง (Build) และการนำโค้ดไปใช้งานจริงเกิดขึ้นโดยอัตโนมัติ สัปดาห์นี้จะมุ่งเน้นการทำความเข้าใจแนวคิด CI/CD และการใช้งานเครื่องมือ GitHub Actions ในการสร้าง Automated Pipeline

2.  สมรรถนะหลัก/ย่อย (Unit of Competence / Element of Competence)
1. เข้าใจหลักการ Continuous Integration และ Continuous Deployment (CI/CD)
2. สามารถใช้งานคำสั่งและไวยากรณ์ (Syntax) เบื้องต้นของ GitHub Actions ได้
3. มีทักษะในการสร้าง Pipeline อัตโนมัติสำหรับการ Build และ Test
4. มีความกระตือรือร้นในการลดขั้นตอนการทำงานซ้ำซ้อน

3.  จุดประสงค์เชิงพฤติกรรม (Behavioral Objective)
1. อธิบายความหมายและประโยชน์ของระบบ CI/CD ได้
2. อธิบายองค์ประกอบของ GitHub Actions (Workflow, Job, Step, Action) ได้
3. เขียนไฟล์ YAML เพื่อกำหนด GitHub Actions Workflow เบื้องต้นได้
4. สร้าง Pipeline อัตโนมัติเพื่อทำการ Build, Test และ Push Docker Image ได้สำเร็จ
5. สรุปความรู้เกี่ยวกับกระบวนการอัตโนมัติและโครงสร้าง YAML ลงในสมุดจด
6. แสดงความสนใจต่องานที่ได้รับมอบหมายได้เป็นอย่างดี
7. ประยุกต์ใช้ CI/CD เพื่อลดข้อผิดพลาดในการตรวจสอบโค้ด
8. ปฏิบัติงานด้วยความรอบคอบและหมั่นตรวจสอบสถานะของ Pipeline

CI/CD (Continuous Integration / Continuous Deployment)
- CI: แนวปฏิบัติที่นักพัฒนาจะส่งโค้ดรวมกันบ่อยๆ (บ่อยครั้งต่อวัน) โดยระบบจะทำการตรวจจับการเปลี่ยนแปลง สั่ง Build และ Test อัตโนมัติ เพื่อให้มั่นใจว่าโค้ดที่รวมเข้ามาใหม่ไม่ทำให้ระบบพัง
- CD: กระบวนการนำโค้ดที่ผ่านการทดสอบจาก CI ไปติดตั้ง (Deploy) บน Production Server อัตโนมัติ เพื่อให้ผู้ใช้เข้าถึงฟีเจอร์ใหม่ได้รวดเร็ว

GitHub Actions
คือเครื่องมือช่วยสร้าง CI/CD Pipeline ที่ให้บริการโดย GitHub โดยจะถูกกำหนดค่าผ่านไฟล์ YAML ที่จัดเก็บในโฟลเดอร์ `.github/workflows/`

องค์ประกอบของ Workflow:
1. Event (`on:`): สิ่งกระตุ้นที่ทำให้ Workflow เริ่มทำงาน (เช่น `push`, `pull_request`)
2. Job (`jobs:`): กลุ่มของขั้นตอนการทำงานย่อย (เช่น `build`, `test`) โดยค่าเริ่มต้น Job จะทำงานขนานกัน
3. Runner (`runs-on:`): เครื่องเซิร์ฟเวอร์จำลอง (VM) ที่ใช้รัน Job (เช่น `ubuntu-latest`)
4. Step (`steps:`): ลำดับขั้นตอนการทำงานย่อยภายใน Job (ใช้ `run:` เพื่อรันคำสั่ง Linux หรือ `uses:` เพื่อเรียกใช้ Action สำเร็จรูป)
