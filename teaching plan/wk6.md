1.  สาระสำคัญ (Concept) 
	ในสภาพแวดล้อมการทำงานจริงของการพัฒนาซอฟต์แวร์แบบ DevOps การทำงานร่วมกันเป็นทีม (Collaboration) ถือเป็นหัวใจสำคัญ การนำ Git มาใช้ร่วมกับแพลตฟอร์มเก็บโค้ดบน Cloud อย่าง GitHub จะช่วยให้ทีมนักพัฒนาสามารถแชร์ จัดการ และรวมซอร์สโค้ด (Merge) กันได้อย่างมีประสิทธิภาพ สัปดาห์นี้จะมุ่งเน้นไปที่การทำงานร่วมกันโดยใช้ระบบกิ่งก้าน (Branch), การเสนอและตรวจสอบโค้ดผ่าน Pull Request (PR), การให้ข้อเสนอแนะผ่าน Code Review รวมถึงรูปแบบการทำงานมาตรฐานเช่น GitFlow หรือ GitHub Flow

2.  สมรรถนะหลัก/ย่อย (Unit of Competence / Element of Competence)
1. มีความเข้าใจความแตกต่างระหว่าง Git (ระบบในเครื่อง) และ GitHub (ระบบบน Cloud)
2. สามารถแตกสาขา (Branch) เพื่อทำงานฟีเจอร์แยกออกจากงานหลักได้
3. มีทักษะในการทำงานร่วมกับผู้อื่นผ่าน Pull Request (PR) และ Code Review
4. สามารถยอมรับความคิดเห็นและสื่อสารกับเพื่อนร่วมทีมอย่างสร้างสรรค์

3.  จุดประสงค์เชิงพฤติกรรม (Behavioral Objective)
1. อธิบายความแตกต่างและหน้าที่ของ GitHub ได้
2. ใช้งานคำสั่ง git branch, git checkout, git push, git pull ได้อย่างถูกต้อง
3. จัดการสร้าง Pull Request เพื่อขอรวมโค้ดเข้าสู่เส้นหลัก (Main branch) ได้
4. ปฏิบัติการจำลองสถานการณ์ Team Workflow เพื่อตรวจสอบและแก้ไขโค้ดร่วมกับเพื่อนได้
5. สรุปกระบวนการทำงานร่วมกันผ่าน Git และบันทึกลงสมุดจด
6. แสดงความเคารพและให้เกียรติความคิดเห็นของผู้อื่นในกระบวนการ Code Review
7. ประยุกต์ใช้แนวทาง Team Workflow ในโปรเจกต์ของรายวิชา
8. สามารถแก้ไขข้อขัดแย้งของโค้ด (Merge Conflict) เบื้องต้นได้อย่างมีสติและรอบคอบ

	-  การเรียนรู้แบบร่วมมือ (Collaborative Learning) อธิบายหลักการ Team Workflow และให้ผู้เรียนจับกลุ่มจำลองการทำงานบน GitHub ผ่าน Pull Request

GitHub คือผู้ให้บริการโฮสต์พื้นที่ฝากโปรเจกต์ Git บนระบบคลาวด์ ซึ่งเปรียบเสมือนโซเชียลมีเดียของโปรแกรมเมอร์ที่มีฟีเจอร์ช่วยให้คนทำงานร่วมกันได้ง่ายขึ้น เช่น การจัดการ Issue, การทำ Code Review, และระบบ CI/CD

หลักการทำงานร่วมกัน (Team Workflow)
- Branch (กิ่งก้าน): กฎสำคัญคือไม่ควรแก้ไขโค้ดที่กิ่งหลัก (main) โดยตรง ทุกคนในทีมควรแตกกิ่งย่อยเพื่อทำฟีเจอร์ของตนเอง (เช่น `git checkout -b feature-a`)
- Push & Pull: ใช้ `git pull` เพื่อดึงโค้ดล่าสุดจากเพื่อนลงมายังเครื่อง และ `git push` เพื่อดันโค้ดของตนเองขึ้นไป
- Pull Request (PR): เมื่อทำฟีเจอร์เสร็จสิ้นในกิ่งย่อย แทนที่จะรวม (Merge) เข้าสู่กิ่งหลักทันที เราต้องสร้างคำขอ "Pull Request" บนหน้าเว็บ GitHub เพื่อให้เพื่อนร่วมทีมตรวจสอบก่อน
- Code Review: เพื่อนในทีมจะทำการอ่านโค้ดที่เปลี่ยนแปลงและให้คำแนะนำหรือสั่งให้แก้ไข ก่อนที่จะกดยอมรับการรวมโค้ด การรีวิวที่ดีต้องติเพื่อก่อ และสุภาพ
- Merge Conflict: บางครั้งสองคนแก้บรรทัดเดียวกัน Git จะสับสนและขึ้นเป็น Conflict ซึ่งต้องให้มนุษย์ตัดสินใจลบส่วนที่ไม่ใช้ออกด้วยมือ
