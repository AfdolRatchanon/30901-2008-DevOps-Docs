1.  สาระสำคัญ (Concept) 
	การทำงานในรูปแบบ Agile เป็นรากฐานที่สำคัญที่ส่งเสริมให้เกิด DevOps เนื่องจากเน้นการทำงานเป็นรอบสั้นๆ และปรับเปลี่ยนได้เร็ว นอกจากนี้การวัดผลสำเร็จในการส่งมอบซอฟต์แวร์ยังต้องอาศัยตัวชี้วัดที่เป็นมาตรฐานอย่าง DORA Metrics (Deployment Frequency, Lead Time for Changes, Mean Time to Recovery, Change Failure Rate) อีกทั้งสิ่งสำคัญพื้นฐานที่สุดในการเริ่มต้นกระบวนการ DevOps คือการตั้งค่า Development Environment (WSL2, VS Code, Git, Node.js) ให้เหมาะสมและมีมาตรฐานเดียวกันเพื่อลดปัญหา "Works on my machine"

2.  สมรรถนะหลัก/ย่อย (Unit of Competence / Element of Competence)
1. มีความเข้าใจความสัมพันธ์ระหว่าง Agile และ DevOps
2. สามารถวิเคราะห์ประสิทธิภาพของทีมได้ด้วย DORA Metrics
3. มีทักษะพื้นฐานในการตั้งค่า Development Environment (WSL2, VS Code, Git)
4. มีความตั้งใจและรับผิดชอบในการลงมือปฏิบัติงานจริง

3.  จุดประสงค์เชิงพฤติกรรม (Behavioral Objective)
1. อธิบายความเชื่อมโยงระหว่าง Agile และ DevOps ได้อย่างถูกต้อง
2. ระบุและอธิบายความหมายของตัวชี้วัด DORA Metrics ทั้ง 4 ตัวได้
3. เตรียมเครื่องคอมพิวเตอร์และติดตั้ง WSL2 ได้อย่างถูกต้อง
4. ติดตั้งและปรับแต่ง VS Code และ Git สำหรับการพัฒนาซอฟต์แวร์ได้อย่างถูกต้อง
5. สรุปเนื้อหาและประเมินผลงานการติดตั้งเครื่องมือได้
6. แสดงความสนใจต่องานที่ได้รับมอบหมายได้เป็นอย่างดีเมื่อครูมอบหมายงานให้ทำ
7. ประยุกต์แนวทางการแก้ปัญหาทางเทคนิคในการตั้งค่าสภาพแวดล้อม
8. ประยุกต์ใช้เครื่องมือในการทำงานได้อย่างรู้คุณค่าและมีประสิทธิภาพ

Agile & DevOps มีความสัมพันธ์กันอย่างแนบแน่น โดย Agile เป็นเหมือนปรัชญาและกรอบการทำงาน (Framework) ที่เน้นความยืดหยุ่น การส่งมอบงานทีละส่วนและการทำงานร่วมกัน ส่วน DevOps เป็นตัวขับเคลื่อน (Enabler) ให้ Agile เกิดขึ้นจริงได้ผ่านการนำเครื่องมือ Automation และแนวปฏิบัติด้าน Operations มาใช้ร่วมด้วย

DORA Metrics เป็นตัวชี้วัดที่ถูกคิดค้นโดยทีมวิจัย DevOps Research and Assessment (DORA) ของ Google เพื่อวัดผลประสิทธิภาพของการนำกระบวนการ DevOps ไปใช้งาน แบ่งออกเป็น 4 ตัวชี้วัดสำคัญ คือ:
1. Deployment Frequency: ความถี่ในการ Deploy ระบบขึ้นสู่ Production (ยิ่งบ่อย ยิ่งดี)
2. Lead Time for Changes: ระยะเวลาตั้งแต่เริ่มเขียนโค้ดจนกระทั่งโค้ดนั้นถูกใช้งานจริงบน Production (ยิ่งสั้น ยิ่งดี)
3. Change Failure Rate: อัตราความล้มเหลวหลังจากการ Deploy (ยิ่งต่ำ ยิ่งดี)
4. Time to Restore Service (Mean Time to Recovery): ระยะเวลาในการกู้คืนระบบเมื่อเกิดปัญหาขัดข้อง (ยิ่งสั้น ยิ่งดี)

การเตรียมพร้อม Development Environment เป็นขั้นตอนที่สำคัญที่สุดในการทำงานแบบ DevOps เพราะถ้าเครื่องมือไม่พร้อมหรือไม่เหมือนกันในทีม จะทำให้เกิดความสับสนและข้อผิดพลาดในการทำงานร่วมกัน (Collaboration)
