1.  สาระสำคัญ (Concept) 
	ระบบควบคุมเวอร์ชัน (Version Control System - VCS) ถือเป็นกระดูกสันหลังของการพัฒนาซอฟต์แวร์และการทำงานแบบ DevOps การใช้เครื่องมืออย่าง Git เพื่อติดตามการเปลี่ยนแปลงของซอร์สโค้ดเป็นทักษะที่ขาดไม่ได้ ซึ่งในสัปดาห์นี้จะมุ่งเน้นไปที่การใช้งาน Git บนเครื่องส่วนบุคคล (Local Repository) ทำความเข้าใจวงจรการทำงาน (Working Directory, Staging Area, Local Repo) คำสั่งพื้นฐาน (init, add, commit, status, log) รวมไปถึงการประยุกต์ใช้คำสั่งขั้นสูงในการแก้ไขข้อผิดพลาดของการจัดการโค้ด (เช่น reset, revert, stash, rebase) เพื่อให้สามารถจัดการไฟล์ในโปรเจกต์ได้อย่างเป็นระบบ

2.  สมรรถนะหลัก/ย่อย (Unit of Competence / Element of Competence)
1. มีความเข้าใจแนวคิดพื้นฐานของระบบ Version Control
2. มีทักษะในการใช้คำสั่ง Git ขั้นพื้นฐานสำหรับการทำงานส่วนบุคคล
3. มีความสามารถในการแก้ไขข้อผิดพลาดในประวัติการทำงานของ Git (Git History)
4. มีความรอบคอบและรับผิดชอบในการบันทึกและจัดการซอร์สโค้ด

3.  จุดประสงค์เชิงพฤติกรรม (Behavioral Objective)
1. อธิบายความสำคัญและวงจรการทำงานของ Git ได้อย่างถูกต้อง
2. ใช้งานคำสั่งพื้นฐาน (git init, git add, git commit) เพื่อติดตามการเปลี่ยนแปลงของไฟล์ได้
3. ตรวจสอบประวัติการทำงาน (git log, git diff) ได้
4. ใช้งานคำสั่งขั้นสูง เช่น git reset, git revert หรือ git stash เพื่อจัดการข้อผิดพลาดได้
5. สรุปผลการเรียนรู้และขั้นตอนการใช้งานคำสั่ง Git ลงในสมุดจด
6. แสดงความสนใจต่องานที่ได้รับมอบหมายได้เป็นอย่างดี
7. ประยุกต์ใช้คำสั่ง Git เพื่อควบคุมเวอร์ชันของโปรเจกต์ตนเอง
8. ปฏิบัติงานด้วยความรอบคอบเพื่อป้องกันการสูญหายของซอร์สโค้ด

Git Basics & Advanced



Git เป็นระบบ Version Control แบบกระจาย (Distributed Version Control System) หน้าที่หลักคือจดจำการเปลี่ยนแปลงทุกอย่างในโฟลเดอร์โปรเจกต์ 
แนวคิดสำคัญ:
- Working Directory: โฟลเดอร์ที่เราทำงานอยู่ (Unstaged)
- Staging Area: พื้นที่พักรอไฟล์ที่เตรียมจะบันทึกการเปลี่ยนแปลง (พร้อม Commit)
- Local Repository: ฐานข้อมูลที่เก็บบันทึกประวัติบนเครื่องของเรา

คำสั่งพื้นฐาน (Git Basics)
- `git init`: เริ่มต้นสร้าง Repository ในโฟลเดอร์ปัจจุบัน
- `git status`: ตรวจสอบสถานะของไฟล์ในระบบ
- `git add <file>`: นำไฟล์เข้าสู่ Staging Area
- `git commit -m "Message"`: บันทึกการเปลี่ยนแปลงจาก Staging เข้าสู่ Repository
- `git log`: ดูประวัติการ Commit

คำสั่งขั้นสูง (Git Advanced)
- `git diff`: ดูความเปลี่ยนแปลงของไฟล์เทียบกับครั้งล่าสุด
- `git reset`: ใช้ยกเลิกสิ่งที่ทำไป (ระวังการใช้ `--hard` ซึ่งจะลบการเปลี่ยนแปลง)
- `git revert`: ยกเลิกสิ่งที่ commit ไปแล้ว โดยการสร้าง commit ใหม่ที่ให้ผลตรงกันข้าม
- `git stash`: พักการเปลี่ยนแปลงปัจจุบันไว้ชั่วคราว เพื่อไปทำอย่างอื่นก่อน แล้วค่อยกลับมาดึง (pop) คืน
