1.  สาระสำคัญ (Concept) 
	การประเมินและนำเสนอ Final Project ถือเป็นจุดสูงสุดของการเรียนรู้ในรายวิชานี้ ผู้เรียนจะต้องนำเสนอผลงานที่สะสมมาตั้งแต่สัปดาห์ที่ 1 ถึง 16 โดยโปรเจกต์จะต้องครอบคลุมการทำงานแบบ End-to-End ตั้งแต่การเขียนโค้ด (Git Workflow) การบรรจุในคอนเทนเนอร์ (Docker) การทำระบบทดสอบและส่งมอบอัตโนมัติ (CI/CD Pipeline) การติดตั้งบนเซิร์ฟเวอร์จริง (Cloud Deployment) และการตรวจสอบสถานะระบบ (Monitoring) นอกจากการทำงานของระบบแล้ว ผู้เรียนยังต้องมีทักษะในการนำเสนอ ตอบคำถามเชิงเทคนิค (Code Review) และอธิบายเหตุผลของการเลือกใช้เครื่องมือต่างๆ ได้อย่างชัดเจน

2.  สมรรถนะหลัก/ย่อย (Unit of Competence / Element of Competence)
1. สามารถบูรณาการความรู้และสร้างระบบ DevOps Pipeline ที่ใช้งานได้จริง
2. มีทักษะในการนำเสนอ (Presentation) และการสาธิตการทำงานของซอฟต์แวร์ (Demo)
3. สามารถตอบคำถามเชิงลึกและอธิบายเหตุผลในการตัดสินใจทางสถาปัตยกรรม (Code Review)
4. มีความกล้าแสดงออก มั่นใจ และรับฟังคำติชมอย่างสร้างสรรค์

3.  จุดประสงค์เชิงพฤติกรรม (Behavioral Objective)
1. สาธิตการทำงานของโปรเจกต์บน Public URL ได้ครบกระบวนการ 
2. อธิบายขั้นตอนการทำงานของ CI/CD Pipeline ของตนเองใน GitHub Actions ได้
3. แสดงความเข้าใจและตอบคำถามเชิงเทคนิค เช่น "ทำไมจึงเลือกใช้เทคโนโลยีนี้" ได้อย่างสมเหตุสมผล
4. เขียนและอธิบายเอกสารประกอบ (README, Runbook) ได้อย่างละเอียด
5. สรุปความรู้และประสบการณ์ที่ได้รับตลอดภาคเรียนลงในสมุดจด
6. แสดงความสนใจต่อผลงานเพื่อน และแลกเปลี่ยนข้อคิดเห็นในชั้นเรียน
7. ประยุกต์ใช้คำแนะนำจากผู้สอนไปต่อยอดในการทำงานจริงในอนาคต
8. ปฏิบัติงานด้วยความรอบคอบ ไม่เปิดเผยข้อมูลความลับ (Secrets) ออกสู่สาธารณะขณะนำเสนอ

5.  กิจกรรมการเรียนรู้ (Teaching / Learning Activities)
	-  การเรียนรู้แบบโครงงานเป็นฐาน (Project-based Learning) นำเสนอผลงานโปรเจกต์รวม (Final Project) ในรูปแบบการสาธิต (Demo) การอธิบาย Pipeline และการสัมภาษณ์เชิงเทคนิค (Code Review)
	เรื่องที่/งานที่ (Sub Topic/Job)  :   Final Project
	หัวข้อที่/งานที่ (Sub  Unit/Main Job)  :  การนำเสนอโปรเจกต์ Task Tracker และระบบ Full DevOps Pipeline
	ขั้นนำเข้าสู่บทเรียน  (Motivation)  
1. ครูอธิบายและเน้นย้ำถึงสัดส่วนคะแนน 20 คะแนน ซึ่งมีความสำคัญต่อเกรดของรายวิชา
2. ครูให้กำลังใจและชี้ให้เห็นว่า ระบบ Pipeline ทั้งหมดที่นักศึกษาทำสำเร็จ คือประสบการณ์ตรงที่สามารถนำไปใส่ใน Portfolio สำหรับสมัครงานได้ทันที
	ขั้นการให้เนื้อหาความรู้  (Information)  
1. ขอบข่ายเนื้อหาหลัก
            	  การนำเสนอ 3 ส่วนหลัก ได้แก่ Demo การทำงาน (Public URL), Pipeline Walkthrough (อธิบายขั้นตอนใน CI/CD), และ Code Review (ตอบคำถาม "ทำไม")
2. แนวทางการจัดกิจกรรมการสอน
              2.1 ชี้แจงกระบวนการและกรอบเวลาการนำเสนอ (กลุ่มละไม่เกิน 10 นาที)
	   2.2 อธิบายข้อห้ามที่ส่งผลให้ถูกหักคะแนนโดยตรง เช่น การเก็บตัวแปร .env ไว้ใน GitHub หรือระบบคลาวด์เปิดเข้าไม่ได้ 
ขั้นการประยุกต์เนื้อหา  (Application) 
1. ให้ นศ. แต่ละคน/กลุ่ม ออกมานำเสนอ Final Project ตามลำดับที่กำหนด
2. ผู้เรียนเปิดหน้าจอแอปพลิเคชันสาธิตการทำงาน (CRUD, Healthcheck) และสาธิตการอ่าน Logs หรือการดูสถานะบนระบบ Monitoring 
3. ผู้เรียนเปิด GitHub Actions และอธิบายทีละขั้นตอนของ Job ที่ทำการทดสอบและ Deploy
		-  สอบถามผู้เรียนเชิงเทคนิค เช่น "การทำ Multi-stage ใน Dockerfile ของโปรเจกต์นี้ มีส่วนช่วยอย่างไรในภาพรวม?"

	ขั้นตรวจผลสำเร็จ  (Progress)
- ครูผู้สอนให้คะแนนตามเกณฑ์ Checklist 5 หมวด (App & Docker, CI/CD, Testing, Production, Documentation) รวม 20 คะแนน
- ผู้สอนกล่าวสรุปผลสัมฤทธิ์และพัฒนาการของผู้เรียนตั้งแต่เริ่มต้นรายวิชา

		3. ผู้สอนสอบถามเหตุผลเชิงเทคนิค (ทำไมจึงใช้เทคโนโลยีนั้น) และให้คะแนนตาม Checklist

แนวทางการตอบคำถาม Code Review
การประเมินวิศวกร DevOps ไม่ได้ประเมินแค่ว่า "สร้างระบบได้หรือไม่" แต่ประเมินว่า "รู้หรือไม่ว่าสร้างไปทำไม" คำถามจึงมักจะเน้นที่เหตุผล:
- ทำไมถึงใช้ Multi-stage Dockerfile? (คำตอบที่คาดหวัง: ช่วยลดขนาด Image สำหรับขึ้น Production และเพิ่มความปลอดภัย)
- ถ้า CI ทดสอบตก จะเกิดอะไรขึ้น? (คำตอบที่คาดหวัง: โค้ดจะไม่ถูกนำไป Build เป็น Image และกระบวนการ Deploy จะถูกระงับ เพื่อกันข้อบกพร่องขึ้น Production)
